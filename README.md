Live Transit aggregates live status, alerts, line maps and vehicle positions for public transport networks worldwide. This is a [Next.js](https://nextjs.org) project bootstrapped with [`create-next-app`](https://nextjs.org/docs/app/api-reference/cli/create-next-app).

## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `app/page.tsx`. The page auto-updates as you edit the file.

This project uses [`next/font`](https://nextjs.org/docs/app/building-your-application/optimizing/fonts) to automatically optimize and load [Geist](https://vercel.com/font), a new font family for Vercel.

## Line catalog and maps

Most realtime feeds only name routes by id. To show every line with its real name, color and geometry, each
source is linked to its static GTFS schedule (`src/connectors/static-gtfs.json`, generated by
`bun scripts/gen-static-gtfs.ts` from the Mobility Database plus hand-mapped overrides).

- `bun run import:static [--force] [id ...]` imports routes and simplified shapes into the `routes` table. Only
  `routes.txt`, `trips.txt` and `shapes.txt` are read, over HTTP Range requests, so even 500 MB feeds import in
  about a minute. The `/api/cron/static` job refreshes catalogs weekly.
- On every ingest, vehicles get route names, modes and colors from the catalog, and sources without their own
  per-line status get one line per route, with state derived from the alerts that name it.
- `GET /api/v1/sources/{id}/live` reads the operator's vehicle feed on request (cached about 10 seconds) when the
  connector supports it; the site's maps poll it and animate vehicles between updates.
- Maps use MapLibre GL with OpenFreeMap tiles (OpenStreetMap data), no API key needed.
